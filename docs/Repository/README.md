# Repository Structure

This folder documents the TRR App repository structure and architecture.

## Generated Documentation

Auto-generated by CI (weekly) and `make repo-map`. These files are artifacts only and are not committed:

- [REPO_STRUCTURE.md](generated/REPO_STRUCTURE.md) - Directory tree listing *
- [REPO_STRUCTURE.mermaid.md](generated/REPO_STRUCTURE.mermaid.md) - Visual structure diagram (Mermaid) * **
- [CODE_IMPORT_GRAPH.md](generated/CODE_IMPORT_GRAPH.md) - Internal import dependencies (Tree-sitter)
- [SCRIPTS_FLOW.md](generated/SCRIPTS_FLOW.md) - Script entrypoints and dependencies (Tree-sitter)

\* *Generated by the Repository Map workflow; may not exist locally until a workflow run or local generation.*
\*\* *Complex diagram may not render in GitHub's Mermaid viewer; download the rendered SVG artifact from the workflow run.*

## Generated Template Diagrams

Checked-in diagrams generated from curated templates:

- [diagrams/git_workflow.md](diagrams/git_workflow.md) - Git workflow (no prescribed branching/worktree strategy)
- [diagrams/system_maps.md](diagrams/system_maps.md) - Architecture and data flow diagrams

[scripts/generate_repo_mermaid.py](../../scripts/generate_repo_mermaid.py) owns both templates and overwrites both outputs on every run. Edit the generator templates, then regenerate and inspect the intended diff. Before regeneration, compare current outputs with the templates and preserve any authored drift in the generator. Output headers repeat this ownership rule.

## Regenerating Locally

```bash
# Generate Tree-sitter-based code diagrams
make repo-map

# Check if diagrams are up to date
make repo-map-check
```

For a bounded template check, load the generator without calling `main()` and
invoke `ensure_git_workflow_template(Path(temp_dir))` and
`ensure_system_maps_template(Path(temp_dir))` in a disposable directory. Compare
those two outputs with the checked-in diagrams; this avoids unrelated import-map
churn. The generator's installed Tree-sitter dependencies are still required.

## CI Updates

The [Repository Map workflow](../../.github/workflows/repo_map.yml) runs weekly (Sunday midnight UTC) and on manual trigger:

1. Generates repo structure using PGSch/graph-git-repo
2. Generates code diagrams using Tree-sitter
3. Opens a PR with any changes

**Setup:** See [WORKFLOW_SETUP.md](WORKFLOW_SETUP.md) for required GitHub secrets configuration.

## Documentation Authority

| Type | Location | Updated By |
|------|----------|------------|
| Generated | `generated/` (artifact-only) | CI workflow + `make repo-map` |
| Generated, checked-in templates | `diagrams/git_workflow.md`, `diagrams/system_maps.md` | Templates in `scripts/generate_repo_mermaid.py` |
| Authored documentation | This README and `WORKFLOW_SETUP.md` | Manual edits |

**Rule:** Edit the owning source for generated outputs. `generated/` remains artifact-only; the two named `diagrams/` files are checked-in outputs. Truly authored documentation is not overwritten by this generator.
